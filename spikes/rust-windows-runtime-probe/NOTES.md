# Rust Windows 运行时资源 Spike 结论

状态：完整原型依赖栈的 10 分钟门槛通过

日期：2026-07-24

## 负载

探针使用 Windows GNU-LLVM 原生工具链，持续执行：

- Tokio 双线程运行时。
- 两个回环 TCP 监听与客户端往返，分别模拟 Hook 与手机连接。
- 每 250 毫秒生成、归并和序列化一次脱敏任务状态。
- 每次状态更新执行一次 ChaCha20-Poly1305 加密。
- 最多保留 12 条任务摘要。
- 每 500 毫秒调用真实 Win32 `GetForegroundWindow`。

## 结论边界

Tokio、Win32 API、双 TCP、JSON 任务归并和加密组合远低于 100MB 与平均
CPU 1% 的原型门槛，第三项高风险技术验证通过。采用原生 Rust 替换 Electron
在资源占用上具备充分余量。

该结果不包含正式托盘 UI、Hook 安装器、二维码窗口、真实 Android 连接和完整
局域网加密握手，也不是正式程序连续四小时的增长验收。正式组件接齐后仍须按
PRD 对整个进程树重新执行 10 分钟与四小时验收。
