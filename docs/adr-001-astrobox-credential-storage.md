# ADR-001：AstroBox 端凭据存储

状态：已接受

日期：2026-07-18

决策人：用户

接受方案：1（令牌仅驻 AstroBox 插件进程内存）

## 背景

PRD 同时要求长期凭据免重复输入，以及手机端凭据使用平台安全存储、不得写入 RPK 或普通配置文本。

AstroBox API 3 当前提供设备、通信、网络、对话框和 UI 接口，但没有 Android Keystore、StrongBox、keychain 或等效秘密存储接口。插件可以写普通 WASI 文件，但无法证明密钥由硬件/系统密钥保护。

## 决策

选择安全优先的临时方案：

- 配对成功后的高熵 Bearer 令牌只驻留在 AstroBox 插件进程内存。
- 不写入 RPK，不写普通 JSON/文本配置，不做可逆“混淆”。
- AstroBox 进程保持运行时，日常打开手环不需要进入插件页。
- AstroBox 被系统杀死、重启或插件重新加载后，需要重新输入电脑地址与临时配对码。

## 已评估方案

1. 保持内存方案：隐私边界最强，但进程重启后需重配。
2. 接受 AstroBox 插件私有文件：体验更好，但不满足严格的 Keystore 语义；令牌泄露影响仅限只读额度，可由 Windows 撤销。
3. 等待 AstroBox 提供安全存储 Host API，再实现免重配。
4. 开发独立 Android 伴侣应用并使用 Android Keystore；范围和维护成本显著增加，且仍需解决与手环通信能力。

用户于 2026-07-18 明确选择方案 1。MVP 不把令牌写入普通文件，也不把“插件私有目录”描述为 Android 安全存储。

## 后果

- AstroBox 进程存活时，用户日常只需打开手环应用，不需要进入 AstroBox 插件页面。
- 蓝牙短暂断开后，插件会重新注册手环订阅，内存令牌仍可继续使用。
- AstroBox 被 HyperOS 杀死、应用重启、插件重载或手机重启后，内存令牌会消失，用户需要从 Windows 托盘生成新的 6 位码并重新配对。
- Windows 端仍只持久化长期令牌的 SHA-256 哈希，并允许用户随时撤销全部配对。
- 若未来公开版本要求完全无感恢复，应优先开发使用 Android Keystore 的独立伴侣应用，或等待 AstroBox 提供等效安全存储 Host API。
