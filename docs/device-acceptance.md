## 安装前

- 三台设备连接同一可信局域网。
- 如果小米 15 开启 VPN，为 AstroBox 或电脑私网地址启用“绕过局域网”；用户已确认该方式能够保持连接。
- 小米 15 的 AstroBox 已获得蓝牙、附近设备和必要的后台运行权限。
- 侧载期间暂时强行停止“小米运动健康”，避免两个应用竞争手环蓝牙连接；完成验收后再测试恢复它时的实际影响。
- 保留旧往返 Spike，直到正式应用验收通过，便于失败时区分“传输环境”与“正式应用”问题。

## 1. Windows 候选包

安装 `dist/Codex Quota Setup 0.3.0.exe`。

验收：

- 安装范围为当前 Windows 用户，不要求管理员权限。
- 因个人侧载包未购买代码签名证书，Windows 显示“未知发布者”属于已知限制；应核对 SHA-256：`27D653E9AD8F6034C4CDC4DB21FEDB777D168C63DD7119149A7F157F43BCB43E`。
- 安装后没有主窗口，通知区域出现青绿色高对比「Codex 额度」托盘图标，不再是空白占位。
- 托盘摘要显示实际额度窗口和 Full reset 数量。
- “显示配对信息…”打开独立二维码窗口；手动地址与 6 位码默认折叠但可复制，窗口在配对码到期时自动关闭。
- “登录 Windows 时自动启动”首次默认为开；手动关闭后，退出并再次打开应用仍保持关闭。

## 2. 小米 15 / AstroBox 插件

在 AstroBox 中导入 `astrobox-plugin/dist/codex-quota-astrobox-0.2.0.abp`，SHA-256：`6197E7DEDA7EBA97084FE5CD261973182463D3D1370EB60362D534B8F014B7C9`。安装后先手动打开一次插件，使其注册 DeepLink。

验收：

- 插件页面标题为「Codex 额度桥接 v0.2.0」。
- 页面明确显示“令牌只保存在本次 AstroBox 进程内”。
- 插件权限只有设备、对话框、设备通信、接收注册、DeepLink 注册和网络；没有短信、联系人、定位、相册等权限。
- 未配对时页面提示从 Windows 托盘打开二维码；“手动输入（高级）”仍可完成原有地址 + 6 位码流程。
- 点击“检测连接并重订阅”后，显示已连接设备数与订阅数。

- “可用重置”与“周额度”字号一致；数量居中，数字有状态色，“次”为白色，到期副标题使用“7月27日到期”的短文案。

## 4. 首次配对

1. 先打开一次 AstroBox 0.2.0 插件，确认页面显示“已准备扫码配对”。
2. Windows 托盘选择“显示配对信息…”，电脑显示二维码。
3. 用小米 15 系统相机扫码，选择在 AstroBox 中打开；应直接进入「Codex 额度桥接」并自动配对，不输入长地址或 6 位码。
4. 不在截图或聊天中发送配对二维码；其中的临时码 5 分钟过期、最多尝试 3 次且成功后立即失效。
5. 配对成功后点击一次“检测连接并重订阅”。扫码失败时才展开 Windows 手动信息，并点击插件“手动输入（高级）”。

升级 AstroBox 0.2.0 会启动新的插件进程，本候选需要重新扫码一次。后续只要 AstroBox 进程内令牌仍在，升级同包名 RPK 0.2.1 不需要再次配对；AstroBox 进程被系统终止后，再从 Windows 托盘生成新二维码即可。

验收：

- AstroBox 显示配对成功及有效订阅数。
- Windows 只保存长期令牌的 SHA-256 哈希；手机令牌只驻内存；手环不接收令牌。
- Windows 托盘“撤销所有已配对设备”能立即让旧令牌失效。

## 5. 正常链路

打开手环「Codex 额度」并计时。

验收：

- 5 秒内显示新快照，或在 5 秒边界显示明确超时；不得无限停留在“等待回包”。
- 只显示服务端实际返回的窗口。当前没有 5 小时窗口时，只显示周额度。
- 周额度显示剩余百分比、动态红/黄/绿颜色和重置日期；不再重复显示进度条或“剩余”。
- Full reset 只显示可用数量和最近到期日；逐条名称、精确到期时间和缓存来源不进入当前极简 MVP。
- 周额度与 Full reset 数量会随使用变化，不能把文档或截图中的数值当作固定期望值。
- 连续快速点击刷新不会产生并发请求。

## 6. 恢复与降级

逐项测试，每项保留一张不含配对码的截图和大致耗时：

1. 关闭并重开手环应用：先显示本地缓存，再刷新。
2. 临时关闭再打开蓝牙，AstroBox 进程保持存活：重新连接后不需要重新配对。
3. 退出 Windows 托盘：手环 5 秒内显示 Windows 不可达并保留缓存。
4. 重启 Windows 服务：配对哈希和最后可信快照仍存在，手机内存令牌仍在时自动恢复。
5. 强行停止并重启 AstroBox：预期显示未配对，从 Windows 托盘生成新二维码并扫码后恢复。
6. 暂停 Windows 同步：手环保留最后可信数据并明确显示暂停/旧数据状态。
7. 到了额度重置时间但 Codex 尚未写入新事件：显示待同步，不推断为 100%。
8. 重新启动“小米运动健康”，观察 10 分钟：记录 AstroBox 与手环是否被抢占断开。这一项决定当前架构能否作为日常 MVP 使用。

## 完成判定

只有上述正常链路、错误降级和 10 分钟连接稳定性都通过，才把正式 MVP 标记完成。若“小米运动健康”与 AstroBox 无法长期共存，候选包仍可证明技术闭环，但日常 MVP 的下一步应改为独立 Android 伴侣应用或其他不争抢主蓝牙连接的桥接方案。
